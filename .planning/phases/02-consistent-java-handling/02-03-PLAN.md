<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inherited environment -> installer | `$env:JAVA_HOME`, `JAVA_TOOL_OPTIONS` and the session `PATH` are user-controlled |
| `java` on PATH -> installer | after the install, the folder saved as `JAVA_HOME` is derived from whichever `java` resolves first |
| installer -> user environment | `Set-UserEnv` writes a persistent user variable read by every new process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09 | Spoofing | `Get-Command java` picks a non-Temurin `java` (Oracle `javapath` shim or another JDK earlier on PATH) | medium | mitigate | The derived folder must pass `Test-JdkUsable`, else `throw` naming the folder (D-08); residual: a different usable JDK 21+ first on PATH is saved, which still satisfies the rule |
| T-02-10 | Information disclosure | `Test-JdkUsable` captured output | medium | mitigate | Output is only matched with `-match`, never written; messages name only the folder |
| T-02-11 | Denial of service | Windows PowerShell 5.1 NativeCommandError on `java -version` stderr | medium | mitigate | Function-local `$ErrorActionPreference = 'Continue'`; decision on `$LASTEXITCODE` and the regex; driver asserts the script-level value stays `Stop` |
| T-02-12 | Repudiation | user `JAVA_HOME` not removed by uninstall | medium | mitigate | Persisted only through `Set-UserEnv`, which records `env:JAVA_HOME`; the existing uninstall `env` arm deletes it |
| T-02-13 | Tampering | stale script-owned user `JAVA_HOME` after a Temurin upgrade | low | accept | Known limitation (RESEARCH Pitfall 7): `Set-UserEnv` warns "already set ... leaving it as-is" while the session gets the new folder; recorded for Phase 3 DOCS-01 |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | No new package installs; `EclipseAdoptium.Temurin.21.JDK` was already the script's winget id |
</threat_model>
