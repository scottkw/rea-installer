## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inherited environment -> installer | `JAVA_HOME` and `JAVA_TOOL_OPTIONS` come from the user's shell |
| `$JAVA_HOME/bin/java` -> installer | the script executes a binary at a user-supplied path |
| installer -> shell profile | the block in `~/.zshrc` / `~/.bash_profile` runs in every new shell |
| installer -> Homebrew | `brew install ghidra` adds dependencies the ledger must account for |

## Planner assumptions (auto-mode resolutions)

- A3 / Pitfall 8 (resolved with the recommended default): Homebrew's `ghidra` formula depends on `openjdk@21`, so ROADMAP success criterion 1's "installs no JDK" cannot hold literally on macOS when Ghidra is installed. The dependency is now installed and recorded by the script instead of being orphaned. With `--no-ghidra`, or with Ghidra already present, a reused JDK 21+ installs no JDK. Rated `reversible` (one conditional line; existing ledger entries stay valid if it is removed).
- `brew_install` in tests always reports "already installed" (stub `list` exits 0); recording `brew:openjdk@21` on a real install is checked by code review only, consistent with Phase 1's FAIL-03 approach.

## Flagged assumptions (edge coverage, unclassified, left unresolved)

- JAVA-03 (unclassified): if the user set `JAVA_HOME` themselves to exactly the script's `openjdk@21` path (for example they installed `openjdk@21` before), `write_profile` writes an identical `export JAVA_HOME=` line into the block. The value is unchanged, not overwritten, but uninstall later removes that block line; the user's own line elsewhere in the profile stays.
- JAVA-04 (unclassified): the rerun check assumes the rerun's shell inherited `JAVA_HOME` from the previous block (a new terminal sourcing the same profile file). A rerun from a shell that never sourced the block, with Ghidra already on PATH and Android off, has no `JAVA_HOME`, so the rewritten block drops it. Homebrew's `ghidraRun` still defaults to `openjdk@21`.
