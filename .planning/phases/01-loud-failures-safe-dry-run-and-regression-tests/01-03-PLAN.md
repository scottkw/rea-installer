## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Tampering | `unpack` partial extract | high | mitigate | Extract into `$TOOLS_DIR/.staging-<name>`, `mv` to target only after success; rerun deletes leftover staging; target existence is the only "installed" signal |
| T-01-11 | Tampering | `fetch` checksum die inside `unpack` | high | mitigate | `archive="$(fetch "$1")" || exit 1` so a checksum mismatch stops the install instead of continuing with an empty path |
| T-01-12 | Tampering | `unpack` cleanup `rm -rf` | medium | mitigate | Only `"$TOOLS_DIR/.staging-$2"` and the fetched archive path are removed; `TOOLS_DIR` is a constant derived from `$HOME` at load; all through `run` |
| T-01-13 | Tampering | Dry run mutations (`install_node`, `rmdir`) | medium | mitigate | `run rm -rf`; dry-run early return in `install_node`; `[ "$dry_run" = true ] ||` before `rmdir`; container check compares a `find ~` snapshot |
| T-01-14 | Denial of service | Uninstall blocked by broken `rea` | medium | mitigate | `|| warn` on the `rea uninstall --purge-data` step; ledger processing continues |
| T-01-15 | Repudiation | Failed package recorded as installed | medium | mitigate | `|| return 1` on each install command so `record "pkg:..."` is unreachable on failure |
| T-01-SC | Tampering | npm/pip/cargo installs | low | accept | This plan adds no package installs; existing pinned versions are unchanged |
</threat_model>
