<objective>
Fix the installer rerun (and uninstall) when the user's shell profile is a symlink, e.g. `~/.zshrc -> dotfiles/.zshrc`.

Diagnosed on the user's Mac: `remove_profile_block` uses an in-place sed edit. BSD sed refuses to edit a symlink in place and `set -e` kills the macOS installer before `rea setup`. GNU sed does not fail, but it replaces the symlink with a regular file. That silently detaches the user's dotfiles link and breaks the Core Value ("never leave the machine silently altered"). Install calls the function before it rewrites the block, and uninstall calls it from its `profile:` arm, so both paths are affected in both bash scripts.

Purpose: a rerun with a dotfiles-managed profile must succeed and keep the link.
Output: the same small change to `remove_profile_block` in `rea-install-macos.sh` and `rea-install-linux.sh`, plus a regression check in `test.sh`.
</objective>
