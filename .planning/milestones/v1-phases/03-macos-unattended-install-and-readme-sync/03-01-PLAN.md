## Planner decisions recorded here

- Seam form (Claude's discretion, D-11): internal constant `TTY_PATH`, assigned unconditionally, never read from the environment. A default-value expansion would let any caller pre-answer "Remove Homebrew?" with a file holding `y`.
- Probe helper (discretion): `have_tty` is a shared helper in each script (3 callers on macOS: confirm, register_agents, install_homebrew; 2 on Linux).
- `register_agents` goes into both scripts, not only macOS. Linux step 9 holds the same branch, the no-shared-code rule wants identical copies, and D-11 asks for step-9 no-tty checks; extracting it lets test.sh reach the Linux branch too.
- `install_homebrew` fetches the installer with `curl -fsSL --proto '=https'` (research prototype), into a variable by plain assignment.
- The failure check for D-06 stubs `curl` to print the script `exit 1` instead of stubbing `env` (research Pitfall 2 alternative): the real `env` and `/bin/bash` run a script that only exits 1, so neither Homebrew's installer nor `sudo` can run, and no `env` stub is left behind.
- Out of scope and unchanged: the uninstall-side Homebrew uninstaller line in `do_uninstall` keeps its inline command substitution (not part of MAC-02/D-06).

## Flagged assumptions (edge probe: MAC-01 and MAC-02 rows are unclassified, left unresolved)

- MAC-01 (unclassified): "a terminal" means `TTY_PATH` opens for reading. A terminal that opens but returns end-of-file on read makes `confirm` answer no (empty reply) without the no-terminal warning; this is not tested and not handled further.
- MAC-02 (unclassified): Homebrew HEAD keeps today's meaning of `NONINTERACTIVE=1` (no Return prompt, `sudo -n` check) (research A2), and macOS sudo keys the `sudo -v` ticket to the controlling terminal so Homebrew's `sudo -n` reuses it under `curl | bash` (research A1). Neither is verified on a real Mac this milestone (VERI-01); the D-06 die catches a failure either way.
